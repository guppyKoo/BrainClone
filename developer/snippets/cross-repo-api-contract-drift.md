# 레포가 갈린 프론트·서버에서 계약이 조용히 어긋나는 지점들

> Edu Vibe(`edu-vibe-front` / `edu-vibe-server`)를 별개 레포로 11일간 굴리며 실제로 겪은 것.
> [[nestjs-mongoose-pitfalls]]가 서버 안쪽의 조용한 실패라면, 이건 **레포 경계를 가로지르는** 같은 형태의 실패다.
> 구조 결정의 근거는 [[2026-09-09-edu-vibe-architecture]].

한 줄로 줄이면 이렇다. **컴파일러가 통과시키는 실패가 가장 비쌌다.**

## 0. 비용이 한 방향으로 몰린다

레포를 나눠서 실제로 얻은 것은 **툴체인 독립**이었다. 프론트가 `typescript-eslint` peer 때문에 TS 6.x에,
`eslint-plugin-jsx-a11y` 때문에 ESLint 9에 묶여 있었는데 그 제약이 서버(TS 5.7)로 번지지 않았다.
컨텍스트가 작아 `CLAUDE.md`를 "프론트에서만 통하는" 규칙으로 좁고 강하게 쓸 수 있었던 것도 실제 이득이다.

반면 **치른 비용은 전부 "계약"에 관한 것이고, 배포·빌드 분리에서 온 것은 하나도 없었다.**
그래서 답은 "레포를 합친다"가 아니라 **"나눈 채로 계약을 고친다"**가 된다.

(주의: TS/ESLint 버전 독립은 별도 Git 레포에서만 되는 게 아니다. 멀티패키지 모노레포도 패키지별
`package.json`·`tsconfig`로 가능하다. 실제로 얻은 건 «별도 패키지 경계»와 «작은 작업 컨텍스트»이고,
별도 레포가 그걸 자연스럽게 강제해 준 것으로 읽는 편이 정확하다.)

## 1. `openapi.json`은 스펙이지 동작이 아니다

학급 API 세 개가 스펙상 `security: none`이었는데 실제로는 전역 `JwtAuthGuard` + `@Roles('teacher')`가 걸려 있었다.
스펙만 보고 붙이면 **401의 원인을 못 찾고 헤맨다.** 결국 서버 소스를 직접 읽어 알아냈다.

codegen을 올려도 이건 해결되지 않는다. 생성 클라이언트는 경로·파라미터·요청/응답 타입의 전사만 없애고,
**행동 계약**(security, 전역 파이프, CORS 노출 헤더, "스펙엔 200인데 실제로는 미구현")은 스펙이 틀리면
**틀린 코드를 그대로 생성**한다. 그래서 순서가 있다.

1. 스펙 신뢰성 확보 (누락된 데코레이터를 채우고, 스펙 생성이 서버 CI에 선다)
2. 그다음 codegen
3. 서버 CI에 **실제 앱 설정으로 부팅한 뒤 주요 엔드포인트의 인증·응답 헤더를 확인하는 계약 테스트**

## 2. 서버의 전역 정책은 프론트에서 보이지 않는다

`forbidNonWhitelisted: true`는 명세 밖 쿼리 파라미터를 **400으로 거절**한다.
브라우저 HTTP 캐시를 우회하려고 특정 화면에서만 붙이던 `_=Date.now()`를 전역 axios 클라이언트로 올리는 순간,
**쿼리 DTO가 있는 엔드포인트가 전부 깨졌다.**

이건 서버 버그가 아니라 **리팩터링이 만든 회귀**다 — 특정 화면 전용 우회를 전역으로 올릴 때
적용 범위가 넓어지는 것을 확인하지 않았다. 해법은 쿼리 파라미터 대신 `Cache-Control: no-cache` 요청 헤더.

> 화면 하나를 위한 우회를 전역 계층으로 승격할 때는 **적용 범위가 넓어진다는 사실 자체**를 확인 항목으로 둔다.

## 3. "서버가 준다"와 "브라우저가 읽을 수 있다"는 다르다

CSV 파일명을 서버가 `Content-Disposition`으로 보내는데 브라우저가 읽지 못해 폴백 파일명으로 떨어졌다.
원인은 서버 CORS의 `exposedHeaders` 한 줄인데, **프론트 PR에서는 고칠 수 없다.**

양쪽에 걸친 설정에는 주인이 없다. 계약 변경 체크리스트에 명시적으로 넣어야 한다.

## 4. 이름 합의가 두 번 걸린다

정렬 계약이 두 번 어긋났다.

1. 서버에 `sort`가 아예 없어 **클라이언트에서 정렬**했는데, 커서 페이지네이션과 겹쳐
   다음 페이지 항목이 이미 정렬된 목록 앞으로 끼어들었다.
2. 서버가 `sort`를 추가한 뒤에도 enum 이름이 달라(`latest`/`oldest` ↔ `newest`/`nickname`) 한 번 더 맞췄다.

한 레포라면 같은 커밋에서 타입이 깨져 즉시 드러난다. **이름만 달라도 양쪽에 매핑 계층이 하나 생긴다.**

## 5. 계약 변경 체크리스트 (실제로 어긋난 넷)

엔드포인트를 추가·변경할 때 최소한 이 넷을 함께 확인한다.

| | 확인할 것 |
|---|---|
| enum | 값이 아니라 **이름**까지 같은 시점에 합의했는가 |
| 응답 헤더 | CORS `exposedHeaders`에 노출돼 있는가 |
| 쿼리 파라미터 | 화이트리스트를 통과하는가 (`forbidNonWhitelisted`) |
| 구현 상태 | 스펙의 200이 **실제로 구현된 것**인가, 미구현 표시가 있는가 |

## 6. 타입이 통과하는 버그 — 전부 테스트로 잡히는 종류였다

`tsc`와 `pnpm build`가 모두 통과하는데 동작만 틀리는 부류.

| 증상 | 왜 안 잡혔나 |
|---|---|
| 라우트 파라미터를 `userId`로 개명했는데 화면은 `studentId`를 읽어 빈 화면 | `useParams()`가 `Record`라 없는 키도 `string \| undefined`로 통과 |
| `?tab=` 정규화를 push로 해서 뒤로가기가 갇힘 | `replace` 누락은 타입 문제가 아님 |
| 객체형 `setSearchParams`가 다른 파라미터를 유실 | 동작 차이일 뿐 시그니처는 정상 |
| `pathname.includes("learn")`이 `/class/learners`를 오인 | 문자열 포함 판정은 언제나 «맞는» 코드 |
| 제출 0/0에서 진행률이 `NaN%` | 0으로 나누는 것은 타입 오류가 아님 |
| 컴포넌트에 쿼리 키를 문자열로 적어 무효화가 조용히 무력화 | 키 팩토리가 바뀌어도 리터럴은 그대로 유효한 배열 |

마지막이 특히 위험하다. 실패가 **에러가 아니라 «아무 일도 일어나지 않음»**으로 나타난다.

> **회귀 방지 테스트 10개가 커버리지 80%보다 값이 있다.** 다만 «테스트»를 한 종류로 묶지 않는다 —
> 0/0과 pathname 판정은 단위, URL·검색 파라미터 보존은 메모리 라우터를 포함한 통합,
> 쿼리 무효화와 401 캐시 정리는 실제 `QueryClient`·인터셉터를 지나는 통합,
> 카드의 touch/focus는 브라우저·실기기 검증이다. 회귀마다 **가장 낮은 비용으로 실제 실패 경계를 통과하는 수준**을 고른다.

## 7. 병렬 브랜치는 «같은 것 두 벌»을 만든다

11일 동안 라우트 경로 상수·`EntryCodeInput`·API 계층 배치·색 팔레트·`QueryClient` 인스턴스가 각각 중복됐다.
원인은 같다 — **브랜치가 병렬로 흐르는 동안 양쪽이 «없으니 만들자»를 각자 했고 합칠 때 둘 다 살아남았다.**
타입도 lint도 «같은 일을 하는 파일이 둘»을 잡아주지 않는다.

`QueryClient`가 대표적이다. Provider가 중첩되면 안쪽이 이기므로 **화면은 정상으로 보이는데**,
401 인터셉터가 비우는 캐시가 다른 인스턴스라 인증이 만료되는 순간에만
«로그아웃됐는데 헤더에 이름이 남아 있는» 형태로 드러난다.

검색을 먼저 하는 습관보다 강한 대책은 **단일 출처와 소유 위치를 코드 구조로 고정하는 것**이다 —
`routePaths.ts`(임포트 0건인 leaf 모듈), 도메인별 query key 팩토리, `queryClient.ts`, 공통 상호작용 훅.

## 8. 문서를 규칙으로 삼으면 문서도 코드처럼 관리해야 한다

코드에서 `studentId`를 전부 `userId`로 바꾼 뒤에도 `CLAUDE.md`·`AGENTS.md`에는 `studentId`가 남아 있었다.
**문서가 먼저 읽히는 파일이라 어긋난 채 두면 다음 작업자가 옛 이름으로 되돌린다.**
"두 파일은 내용이 같아야 한다"고 규정해 뒀는데도 머지 과정에서 갈렸다 —
**사람이 지킬 것이 아니라 검사로 강제할 대상**이다.

## 9. lint가 잡는 경계를 문서에 적어 둔다

`eslint-plugin-jsx-a11y`가 잡는 것은 네 가지뿐이다. 아이콘만 든 일반 `button`이나 의미 없는 `alt` 문구는 통과한다.
`token-lint`도 토큰 **오타**만 잡고, 존재하지만 **틀린** 토큰은 통과한다.
그래서 «통과하지만 문제인 형태»를 문서에 적어 두는 것이 실제로 리뷰에서 쓰였다.
시안 구현은 토큰 이름이 아니라 **숫자로 읽고 브라우저에서 실측**한다.

## 10. SSE는 axios로 읽을 수 없다 — 그 함수만 클라이언트 밖에 산다

axios는 브라우저에서 XHR로 동작해 **응답을 조각 단위로 읽을 수 없다.**
스트리밍은 `fetch` + `response.body.getReader()`로 직접 불러야 하고,
그러면 **`baseURL`과 `Authorization`을 손으로 붙이게 되며 인터셉터를 타지 않는다.**

이게 조용한 함정인 이유는 **그 함수만 401 자동 처리·토큰 부착 규칙 밖에 있다**는 사실이
호출부에서 보이지 않기 때문이다. 함수 주석에 "이 함수만 `apiClient`를 쓰지 않는다"를 명시했다.

부수 효과 하나 — **EventSource를 쓰지 않으므로 «SSE에 토큰을 어떻게 싣는가»(쿼리 파라미터 vs 쿠키)라는
문제 자체가 사라졌다.** POST + `Authorization` 헤더면 된다.
서버도 대칭으로 짠다: **첫 청크를 얻기 전에 인가를 끝내야** 실패가 SSE 프레임이 아니라
평범한 403/404로 나간다(헤더를 열기 전에 제너레이터를 한 번 `next()` 한다).

## 11. 값이 없는 필드는 `null`이 아니라 키 자체가 빠진다

전역 `ClassSerializerInterceptor`가 `excludeExtraneousValues`로 돌면서 `undefined`를 그대로 두기 때문이다.
**프론트는 `null` 체크가 아니라 optional 체크를 해야 한다.**

응답 예시를 문서에 적을 때 이 사실을 함께 적는다. 안 적으면 프론트가 `=== null`로 짜고,
그 분기는 **영영 참이 되지 않는다** — 에러가 아니라 «아무 일도 일어나지 않음»이다.

## 12. 런타임에 주입할 값과 빌드에 굽는 값을 가른다

한 이미지를 dev·stage·운영에 그대로 쓰려면 환경마다 다른 값은 런타임에 읽어야 한다
(`index.html`이 번들보다 먼저 `/config.js`를 불러 `window.__CONFIG__`에 담는 방식).

**그렇다고 전부 런타임으로 옮기면 안 된다.** API base URL이 그 경우다 —
nginx가 `/api`를 백엔드로 프록시하고 그 경로와 **짝**이므로, 런타임에 바꿀 수 있게 두면
**nginx 설정과 어긋난 값이 화면에만 남는다.** 무엇이 어느 쪽인지 문서에 적어 두는 것이 규칙이다.

주의할 전제 둘 —

- **읽는 순서에 의존한다.** `config.js`가 `<head>`의 일반 스크립트이고 번들이 `type="module"`(defer)이라
  항상 먼저 실행된다. `index.html`의 스크립트 순서를 바꾸면 전제가 깨지고,
  증상은 예외가 아니라 **CDN이 안 붙은 주소**로만 드러난다.
- **`??`는 키가 없을 때만 폴백한다.** 배포가 준 빈 문자열은 «쓰지 않는다»는 뜻으로 존중된다 —
  `||`로 쓰면 그 의도가 뒤집힌다.

## 13. 반례 — 모노레포에서도 똑같이 났다 (INOS, 2026-09-09)

이 문서 전체가 "레포가 갈려서 생긴 비용"이라는 틀 위에 서 있는데, **그 틀이 부분적으로 틀렸다.**

INOS는 pnpm workspace + Turborepo **단일 레포**에 서버·웹이 같이 있고 DTO 타입까지 공유한다.
그런데 같은 형태의 실패가 두 건 났다.

- 서버가 `bookIsbn`을 받아 도서를 확정하는 경로를 **생성·수정·재시도 세 곳에** 갖고 있었는데
  웹이 한 번도 호출하지 않았다. 그 결과 `bookWork`이 붙은 모임이 **하나도 없었다.**
  영화는 검색해서 `movieTmdbId`를 보내는데 책만 손으로 친 문자열을 보내고 있었다.
- `.env`와 `.env.example`에는 API 키가 있는데 **`docker-compose.yml`의 `environment` 블록에 없었다.**
  컨테이너로 전달되지 않아 프로덕션에서 두 검색이 조용히 계속 503이었다.

교훈의 방향이 바뀐다.

> **원인은 레포 경계가 아니라 «호출되지 않는 코드는 타입 시스템에 존재하지 않는다»는 사실이다.**
> 타입 공유는 "부르면 모양이 맞는가"만 보장하고 "부르기는 하는가"는 보장하지 않는다.
> 모노레포는 §1~§4의 **모양 불일치**를 지워주지만, **미호출**과 **계층 사이의 빈칸**은 그대로 남는다.

레포를 합쳐도 남는 종류를 따로 적어 둔다.

| 실패 | 모노레포가 막아주나 |
|---|---|
| 응답 필드 이름/타입 불일치 | **막아준다** (공유 DTO) |
| 서버에 있는데 아무도 안 부르는 엔드포인트 | 못 막는다 |
| 코드가 읽는 env가 배포 매니페스트에 없음 | 못 막는다 |
| 큐/잡의 "설정했는데 발동 안 함" | 못 막는다 |

셋 다 **에러를 내지 않는다.** 타입체크·빌드·배포가 전부 통과한다.
찾는 방법은 타입이 아니라 **역방향 탐색**뿐이다 — 서버 라우트 목록을 뽑아 클라이언트에서
호출처를 grep하고, 코드가 읽는 env 키를 뽑아 배포 매니페스트와 차집합을 낸다.
