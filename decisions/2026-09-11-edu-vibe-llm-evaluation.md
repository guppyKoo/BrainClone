# 결정: Edu Vibe LLM 품질을 두 곡선으로 측정한다

Edu Vibe 서비스 코드는 e2e와 테스트로 품질을 검증하지만, 제품의 핵심인 LLM 출력은 현재
프롬프트만으로 관리한다. 모델·TokenHub 라우팅·Langfuse 프롬프트·교안·입력 분포는 레포 커밋 없이
변할 수 있으므로, 테스트가 모두 GREEN이어도 LLM 품질은 보증되지 않는다.

따라서 프롬프트나 모델을 먼저 개선하지 않고, **무엇이 언제 나빠졌는지 검증하고 추적하는 평가 체계**를
먼저 구축한다. 원천은 [Notion 문서](https://app.notion.com/p/EDU-VIBE-LLM-3d74e6997fb080cc9476c45736aec07c)다.

## 확정한 원칙

1. LLM 품질을 단일 평균 점수로 축약하지 않는다.
2. 학생 입력의 **명세량 `S`**를 가로축으로 두고 **품질 `Q(S)`**와 **정정률(S)** 두 곡선을 함께 본다.
3. `S`는 토큰 수가 아니라 대상·속성·값·배치·상호작용 등 **제약 술어 수**다.
4. `Q`는 작동성 게이트와 의도 충족·보존성·적정성·학습성 축으로 분리한다.
5. 정정은 정정 발화 자신의 `S`가 아니라 **정정을 유발한 직전 원인 턴의 `S`**에 귀속한다.
6. 측정 시스템은 제품 밖에 두며, 제품은 버전과 실행 메타를 포함한 데이터를 내보내는 데까지만 책임진다.
7. LLM은 `S`와 실행 가능한 검사 항목을 입력당 한 번 생성해 저장하지만 **점수는 프로그램이 매긴다**.
8. 원본과 LLM 해석 산출물을 보존하고 모든 점수에 `scorerVersion`을 붙여 과거 데이터를 재채점한다.
9. 미성년자의 대화·코드 원문이 제품 밖으로 나가므로 식별자는 전용 해시로 바꾸고 이름은 내보내지 않는다.

목표는 **낮은 `S`에서도 높은 절편을 갖고, 학생이 AI 실패를 고치느라 추가 설명을 하지 않는 상태**다.
주 KPI 후보는 `Q(S≤2)`의 p10과 `정정 명세량 / 전체 명세량`이다.

## 축과 대응 수단

| 축 | 질문 | 주요 대응 |
|---|---|---|
| 작동성 | 브라우저에서 뜨는가 | 서버 검증·자기수정 |
| 의도 충족 | 시킨 것을 했는가 | 컨텍스트 재구성·교안 주입 |
| 보존성 | 안 시킨 것을 지우지 않았는가 | 현재 코드 주입·patch 출력 |
| 적정성 | 시킨 것만 했는가 | 출력 범위 계약 |
| 학습성 | 학생이 읽고 배울 수 있는가 | 시스템 프롬프트 |

보존성과 적정성은 모두 요청 밖 변경을 보지만 방향과 대응이 달라 별도 축으로 둔다. 특히 현재
`ChatService.sendStream`이 최신 `artifact.aiCode`를 첫 턴에만 넣어 학생의 직접 수정이 다음 턴에
사라질 수 있으므로, 보존성 저하는 모델보다 컨텍스트 구성 문제일 수 있다.

## 기각한 접근

- 제품 안에서 측정: 채점기 변경이 제품 배포가 되고 과거 재채점이 어려워진다.
- thumbs를 KPI에 포함: 재현되지 않고 사용자의 선택 편향과 지표 유도에 취약하다.
- 검증하지 않은 LLM judge 점수: 사람 라벨과의 일치도를 확인하기 전에는 신뢰하지 않는다.
- BLEU·임베딩 유사도: 정답이 실행 가능한 HTML인 제품에 텍스트 유사도는 핵심 품질을 재지 못한다.
- 상상으로 큰 골든셋 생성: 실제 K-12 입력 분포와 멀어지고 운영되지 않는다.
- 평가 전 파인튜닝: 개선 여부와 롤백 근거를 만들 수 없다.
- 학생 단위 A/B: 같은 교실에서 답변 경험이 갈리면 교사가 수업을 진행하기 어렵다. 학급 단위만 허용한다.

## 구현 전에 남은 결정

- 입력 계약: 스냅샷 export, 이벤트 스트림, read-only 조회 중 선택
- Edu Vibe 전용 시스템인지 여러 제품을 수용할지
- 원문 보관 기간과 재채점 가능 기간
- 회귀 게이트 결과를 소비해 배포를 막는 주체
- 축 가중치와 첫 턴 처리
- 실제 로그에 따른 `S` 구간과 술어 추출 규칙
- 정정 판정 창 크기와 적정성 허용치 `k`
- 최신 코드를 매 턴 LLM 컨텍스트에 넣을지

## 첫 구현 순서

문서의 최소 시작점은 **보존성 단일 축**이다. 코드펜스 파싱과 DOM diff만으로 시작할 수 있고 LLM이
필요 없다. 이후 `S` 추출과 구간별 곡선을 붙이고, LLM이 체크리스트를 생성해야 하는 의도 충족은
마지막에 구현한다.
